# 다음 작업

이 문서는 저장소 초기화 이후의 작업 순서와 각 단계의 확인 결과를 정의합니다.
작성일은 2026-11-17입니다.

## 1. 권장 환경의 기준 정리

- [ ] Windows 네이티브 환경과 WSL의 선택 조건을 정리합니다.
- [ ] 셸, Git, 패키지 설치, 런타임 관리의 역할을 구분합니다.
- [ ] 이미 설치한 도구를 활용하는 조건을 정합니다.
- [ ] 각 제안의 공식 근거와 확인 방법을 연결합니다.

결과는 [Windows 개발환경 제안](windows-environment.md)에 반영합니다.

## 2. 환경 점검 기능 구현

- [ ] 첫 점검 항목과 결과 형식을 정합니다.
- [ ] 필요한 구현 언어와 최소 런타임을 선택합니다.
- [ ] 환경을 변경하지 않는 점검을 구현합니다.
- [ ] 도구 존재, 도구 부재, 실행 실패를 실제 결과로 구분합니다.

점검 기능을 재실행해도 환경이 변경되지 않는지 확인합니다.

## 3. Codex 플러그인 패키지 구성

- [ ] 점검 절차와 사용법을 Skill로 작성합니다.
- [ ] 필요한 지원 파일과 실제 실행 진입점을 패키지에 포함합니다.
- [ ] 매니페스트와 참조 경로를 검사합니다.
- [ ] Codex에서 기능을 발견하고 사용할 수 있는지 확인합니다.

독립 실행의 성공과 Codex에서의 사용 성공을 별도로 기록합니다.

## 4. 설정과 사용 지원 확장

- [ ] 요청한 범위의 변경 계획과 적용 기능을 구현합니다.
- [ ] 변경이 없는 경우와 재실행을 처리합니다.
- [ ] 실제 개발 프로젝트의 기존 명령으로 사용 흐름을 확인합니다.
- [ ] 검증한 범위에 맞춰 사용 문서를 작성합니다.

배포와 설치 방식은 사용 가능한 패키지를 확인한 뒤 정합니다.
