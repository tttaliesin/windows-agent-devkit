# Windows 개발환경 진단

이 Skill은 로컬 진단 CLI의 첫 구현을 실행하는 절차입니다.
실행 전제조건은 Node.js 24 이상과 PowerShell 7입니다.
명령은 설치된 이 플러그인의 루트에 있는 `src/cli.mjs`를 사용합니다.
현재 작업 디렉터리를 플러그인 루트라고 가정하지 않습니다.

## 실행

사용자가 점검할 프로젝트 경로를 확인합니다.
플러그인 루트와 프로젝트 경로는 별도로 취급합니다.
확인한 실행 파일과 각 인수를 별도로 전달할 수 있는 셸·프로세스 기능을 사용합니다.

```text
node "<플러그인 루트>/src/cli.mjs" --project "<프로젝트 경로>" --format json
```

기본값은 프로젝트 선언에서 필요한 언어를 선택합니다.
특정 계열의 점검을 요청받으면 `--languages node,python`처럼 범위를 명시합니다.
컨테이너 선언만 있는 경우에는 호스트 언어 도구의 설치 요구를 확정하지 않습니다.
호스트에서 직접 개발하는 요구를 확인하면 `--native`로 언어 도구 점검을 명시합니다.
WSL 호스트 확인에는 `--wsl`을 사용합니다.
컨테이너 클라이언트 확인에는 `--containers`를 사용합니다.
Process Compose 메타데이터 확인에는 `--process-compose`를 사용합니다.
보고서 저장을 요청받으면 `--output`에 요청한 파일 경로를 전달합니다.
기존 보고서 파일은 덮어쓰지 않습니다.

## 결과 해석

보고서의 `checks`는 P0 22개 항목의 현재 관찰과 미확인 범위를 포함합니다.
`deferredChecks`는 아직 실제 실행을 구현하지 않은 P1 항목입니다.
`pass`는 해당 항목의 명시한 확인 범위만 충족했다는 뜻입니다.
`fail`은 실행 문맥의 명령 부족이나 확인한 프로젝트 요구 위반입니다.
`unknown`과 `skipped`를 성공으로 바꾸어 설명하지 않습니다.
프로젝트 요구 충족·공식 지원 상태·권장 구성 일치를 각각 설명합니다.
공식 지원 상태는 첫 구현에서 자동 조회하지 않습니다.

실제 선택된 실행 파일과 조회 버전을 근거로 설명합니다.
진단용 PowerShell의 관찰을 사용자 대화형 셸이나 앱 통합 터미널의 설정으로 일반화하지 않습니다.
기존 관리자가 정상 동작해도 적용되는 mise 권장안과 유지 예외를 설명합니다.
C#의 공식 .NET SDK 설치는 mise 권장 구성의 예외입니다.
Nushell은 선택 도구입니다.

## 실행 경계

진단 중 설치·업데이트·로그인·프로필 변경·PATH 변경을 수행하지 않습니다.
관리자 proxy의 자동 다운로드나 환경 동기화를 유발하지 않습니다.
WSL 배포판·컨테이너 엔진·TUI·개발 서비스를 기동하지 않습니다.
Process Compose 설정의 명령이나 환경변수 표현을 평가하지 않습니다.
확인되지 않은 실행은 미확인 사유와 후속 확인 방법으로 설명합니다.
전환을 요청받으면 진단 결과를 바탕으로 변경·보존·검증·복구 범위를 먼저 구체화합니다.
이 첫 구현에 없는 설정 변경이나 서비스 실행 기능을 제공한다고 주장하지 않습니다.

상세한 구현 범위는 `../../docs/diagnostic-cli.md`를 읽습니다.
